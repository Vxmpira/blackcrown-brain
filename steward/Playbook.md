## Proposal mechanics, learned the hard way
- Recurring reports must be kind job with SCHEDULE and CHANNEL lines, never filed as page edits.
- Content edits need an exact CURRENT anchor that exists in the file. Route edits to corvid, who has the repo.
- Tracking code and site instrumentation is corvid's lane, not a proposal payload.
- Site wide link edits go to corvid as an assignment with a live verification step.
- Post proposals need the full https MEDIA link from the render delivery.
- Before filing any digest, read SERVER JOBS. Reply tracking, traffic and UTM digests already exist.
- Do not assign SEO work to unrouted pages.
- Job 114 (per-click UTM rows for Herald) is done and live. Do not refile.
- A page that fails the same guard twice is not refiled. Diagnose the source first, then refile once with counts.
- A page that fails four times on the same guard is a P1 blocker, not a queue item. No new filing until the source line and live counts are in hand.
- Observer page (107, 109, 111, 113): still blocked on duplicate head tag. The source line must come from Corvid, the repo holder, not from a paste.
- When a desk asks whether a fix is live, answer from the ledger: the last guard result stands until a DONE line says otherwise.
- Owner rulings (titles, prices, direction) route to Regent for the owner. Steward routes, never decides.

## Delegation hygiene
- A repair brief names the exact strings to replace and the file they live in.
- A gate needs the copy in its own input. A project note saying a text arrived does not clear the gate; re-send the whole text to the gate.
- Gist truncation (2026-10-28): a draft that stops mid word (for example ending at "korvus.indus") is not a text. Reject it at the source and re-task Crier for a whole
